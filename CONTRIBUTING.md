# Contributing to Viloja

Thanks for your interest in Viloja. The project is in an early planning stage, so small, evidence-backed contributions are especially useful.

## Before starting

- Check the README and the documents in `docs/`.
- For a substantial change, open an issue first so the direction can be discussed.
- Do not describe a protocol, transfer mode, or device combination as supported unless it has been tested and the evidence is documented.
- Keep Quick Share and KDE Connect integrations independent; do not merge protocol-specific logic into the shared UI.

## Useful contributions

- Reproducible protocol and compatibility research.
- Licensing and dependency audits.
- Small proof-of-concept experiments.
- GNOME/GTK4/libadwaita UX improvements.
- Clear bug reports with steps to reproduce, logs, and relevant hardware details.

## Pull requests

1. Explain the problem and the proposed change.
2. Keep changes focused and update documentation where needed.
3. Include test steps and results. Clearly distinguish tests you ran from assumptions.
4. Never include personal files, private device identifiers, secrets, or unredacted logs containing sensitive information.

## Code of conduct

Be respectful, constructive, and welcoming. Critique ideas and implementations, not people.
